実装日: 2026-11-18
実装: `src/mk8dx/runner.py`（新規）、`pipeline.verify_result_candidate`、
`db.approve_race_result / delete_race_result / race_result_entries`、
`server.py` の review API と live API、`web/admin.html` の
要確認セクションとライブ操作。テスト全58件合格。
検証ツール `tools/step5_check.py`。

これで設計書の主要フロー（検出→OCR→名寄せ→集計→オーバーレイ
反映→要確認の承認）が一通りつながった。

## ライブランナー（runner.py）

フレーム源から独立した中核ループ。step(frame, now) を検知周期で
呼ぶだけで状態機械と RaceProcessor が連動する。

- WAITING_RACE: 名前列インクで候補を検出したら、順位列の数字OCR
  （verify_result_candidate）で本物か検証してから検出状態に入る。
- RESULT_DETECTING: 観測を蓄積し、割り当てが安定したら確定。
  確定直前に最終フレームをフェーズ判別し、累計画面だったら
  レースとして処理せず照合に回す（Aを見逃したケースの安全弁）。
- 確定できないレースは is_valid=False で保存し AWAITING_REVIEW。
  approve_pending / discard_pending が DB・累計・状態機械を
  まとめて進める（サーバーの review API と管理画面のボタン）。
- COOLDOWN: 画面が消えて最低時間が過ぎたら次レースへ。その間に
  フェーズBが映れば、自前累計との照合を1回だけ実行し、
  不一致を警告イベントにする。Bの名前は選手名簿で名寄せしてから
  照合する（学習はしない）。
- サーバー: POST /api/live/start（別スレッドで仮想カメラ駆動）/
  stop、GET /api/live/status。カメラが開けない場合はエラーが
  ステータスに残り、サーバー自体は落ちない（実機なしで確認済み）。

## エンドツーエンド検証（実動画 lounge_710.mp4、レース3）

動画を0.5秒間隔でサンプリングして runner に流した結果:

- レース前のプレイヤー紹介画面（名前列インクが高い）は順位列検証で
  すべて棄却され、誤検出ゼロで本物のリザルトだけが検出状態に入った。
- レース3: 検出→確定（埋め合わせ2行のため要確認）→模擬承認→
  COOLDOWN。チーム集計は xı 19 / FR 19 / racist 11 / Xb 12 /
  RR★ 10 / A 11（合計82）で正解と一致。
- COOLDOWN 中にフェーズBが映り、照合が実行された。この検証の
  セッションにはレース1・2の結果がないため、累計の不一致が
  検出されるのが正しい挙動（画面の累計 31/29/24… に対し
  自前集計はレース3分のみ）。名前の名寄せも効いており、
  RR★ 2名が別々に照合された。唯一 'あまあ' という断片読みが
  名寄せできず「集計側に存在しません」になった。

## 検証中に見つけて直した問題

1. **候補検証の型不一致**: recognize_digits_en は int を返すのに
   文字列と比較していたため、検証が全フレームで失敗した。
   int 比較に修正（受け入れ済みフレームで順位1・2が一致して通過）。
2. **紹介画面の誤候補**: 当初は名前列インクだけで検出状態に入り、
   動画序盤で3回誤って入った。順位列検証の追加で解消した。
   なお検証に失敗した候補は1秒間再検証を抑制し、無駄なOCRを避ける。

## 残っている課題

1. 実機（OBS仮想カメラ＋Switch実況）での通し確認は未実施。
   このVMにはカメラがないため、ライブ開始のエラーパスまでが
   検証範囲。実機では検知周期0.4秒・OCR負荷の実測が必要。
2. フェーズBの名前OCRは断片化しやすく（'あまあ' の例）、
   照合の名寄せ成功率が課題。ハイライト行アンカー（配信者本人は
   常にRR★）や、B専用の読み取り改善が候補。
3. セッション開始をまたぐ累計照合は、途中から観戦を始めた場合に
   上記のとおり不一致になる。運用では対戦開始からライブを回す前提。
4. processor と状態機械はライブスレッドと simulate_race で共有
   されるため、同時実行は想定していない（個人利用の範囲）。
