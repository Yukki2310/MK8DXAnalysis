テスト全54件合格。検証ツール `tools/step4_check.py`。

## 実装したもの

### RaceProcessor（processor.py）

フェーズA表示中の複数フレーム観測を蓄積し、安定したら
名寄せ→チーム判定→集計までを行う統合層。

- 順位ごとに名前の多数決でコンセンサス観測を作る（同数は
  最後に観測された表記を優先。アニメーション完了後の読みが
  最も正しいため）。
- 安定判定は「試し照合（学習なし）の割り当て列が stable_frames 回
  連続で同じ」。生読みの揺れではなく、最終結果である割り当ての
  安定を見る。学習は確定時に1回だけ行う。
- 振り分け: 全行が名寄せでき、埋め合わせ（低信頼）がなく、
  クラスタリングが成立すれば confirmed。欠ければ暫定結果つきで
  awaiting_review。埋め合わせはステップ3で全件正しかったが、
  消去法は推測なので自動確定の根拠にしない、という方針。

### パイプライン橋渡しとサーバー

- `pipeline.extract_observations`: フレームから12行分の
  観測（名前＋国旗署名）を抽出する。実フレームで名前は
  ステップ2の読みと一致、国旗署名は12/12抽出できた。
- サーバー: `GET/POST /api/roster`、`DELETE /api/roster/{id}`、
  `POST /api/simulate_race`（生の名前12名→名寄せ→集計。
  confirmed のときだけ is_valid=True で保存し、状態機械を
  AWAITING_REVIEW に倒す）。ロスターはセッションをまたいで保持。
- 管理画面: ロスター登録セクション（登録・一覧・削除）と
  照合テスト投入欄を追加。
- スモークテスト済み: セッション開始→12名登録→実測の生読み投入で
  awaiting_review（低信頼2件のみ理由）＋正しいチーム集計、
  クリーンな名前では confirmed、削除APIも動作。

  xı 19 / FR 19 / racist 11 / Xb 12 / RR★ 10 / A 11（合計82）。

- レース1（open、ロスターはレース3・4用）: 未照合は2行
  （'ths' と 'メ念れえあまあ'）で awaiting_review に落ちた。
  ただし 'Rev' が RR★ に誤って吸着した（コスト1.6）。短い名前の
  誤受理は閾値だけでは防ぎきれないので、未照合が1行でもある
  レースは必ず人手確認に回る現行方針が安全弁になる。

## 検証中に見つけて直した問題

**断片読みによる枠の横取り**: 1文字のゴミ読み '-' は編集距離の
絶対値が小さいため 'RR★' の枠を正規の化け読み '日日-' より
安く奪い、11位と12位が入れ替わった（ステップ3のモードAでは
国旗ボーナスが偶然これを防いでいた）。name_cost に断片ペナルティ
（観測が正規名の半分未満の長さなら不足文字数×0.8を加算）を
追加して解消。ステップ3の検証結果に回帰がないことも再確認した。

## 残っている課題（次ステップ候補）

1. ライブ配線: キャプチャ（OBS仮想カメラ）→パネル領域の静止判定→
   classify_phase→extract_observations→RaceProcessor という
   メインループを server に組み、状態機械（state.py）の遷移と
   接続する。今回の simulate_race はその形を先取りしたもの。
2. AWAITING_REVIEW の承認フロー: 管理画面で暫定結果を見て
   承認/破棄するUI（状態機械側は approve_pending/discard_pending
   実装済み）。承認時に is_valid を更新する保存経路も必要。
3. フェーズBが来たレースでは、確定済み集計と
   cross_check_standings で照合し、不一致なら警告する。
4. ハイライト行アンカー: 配信者本人の行（黄色）を検出して
   エントリに固定ひも付けすると、同行の化け読み耐性が上がる。
